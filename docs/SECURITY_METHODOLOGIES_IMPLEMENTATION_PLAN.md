# План внедрения методологий безопасности

## ✅ Что уже сделано

1. **Анализ методологий** - создан документ `SECURITY_METHODOLOGIES_INTEGRATION.md`
2. **Схема БД** - создан файл `services/database/security_methodologies_schema.sql`
3. **Базовые сервисы**:
   - `services/security_methodology_service.py` - управление методологиями
   - `services/security_testing_service.py` - управление тестами и проектами
4. **API endpoints** - добавлены в `services/backend/app.py`

## 📋 Следующие шаги

### Этап 1: Инициализация БД (1 день)
1. Применить схему БД к существующей базе данных
2. Загрузить базовые методологии (OWASP WSTG)
3. Создать скрипт инициализации

### Этап 2: Загрузка данных методологий (3-5 дней)
1. **OWASP WSTG**: Загрузить все категории и тесты из официальной документации
2. **OWASP MASTG**: Загрузить тесты для мобильных приложений
3. **OSSTMM**: Загрузить структуру операционных тестов
4. **NIST SP 800-115**: Загрузить этапы и рекомендации
5. **PCI DSS**: Загрузить требования к тестированию

### Этап 3: UI компоненты (5-7 дней)
1. Страница методологий (`/security/methodologies`)
2. Страница проектов (`/security/projects`)
3. Страница выполнения тестов (`/security/tests`)
4. Страница результатов (`/security/results`)
5. Dashboard соответствия (`/security/compliance`)

### Этап 4: Интеграция с уязвимостями (2-3 дня)
1. Автоматическое создание уязвимостей из результатов тестов
2. Связывание тестов с существующими уязвимостями
3. Приоритизация на основе результатов тестов

### Этап 5: Отчетность (3-4 дня)
1. Генерация технических отчетов
2. Генерация executive отчетов
3. Генерация compliance отчетов
4. Экспорт в PDF/HTML/DOCX

### Этап 6: Автоматизация (5-7 дней)
1. Интеграция с инструментами автоматизированного тестирования
2. API для внешних инструментов
3. Планировщик тестов
4. Уведомления о результатах

## 🔧 Технические детали

### Структура данных методологий

Каждая методология будет храниться в формате:
```json
{
  "methodology": {
    "name": "OWASP WSTG",
    "version": "4.2",
    "categories": [
      {
        "code": "WSTG-INFO",
        "name": "Information Gathering",
        "tests": [
          {
            "code": "WSTG-INFO-01",
            "name": "Conduct Search Engine Discovery",
            "steps": [...],
            "severity": "info"
          }
        ]
      }
    ]
  }
}
```

### Интеграция с существующей системой

1. **Связь с уязвимостями**: Результаты тестов автоматически создают уязвимости в системе
2. **Приоритизация**: Использование результатов тестов для приоритизации уязвимостей
3. **Отчетность**: Объединение данных тестов и уязвимостей в единые отчеты

## 🚀 Быстрый старт

### 1. Применить схему БД
```bash
psql -h 10.0.88.11 -U admin -d vuln_db -f services/database/security_methodologies_schema.sql
```

### 2. Загрузить базовые методологии
```python
from services.security_methodology_service import security_methodology_service
security_methodology_service.load_owasp_wstg()
```

### 3. Создать тестовый проект
```python
from services.security_testing_service import security_testing_service
project_data = {
    'project_name': 'Test Web Application',
    'methodology_id': 1,  # OWASP WSTG
    'target_type': 'web',
    'target_urls': ['https://example.com'],
    'scope': 'Public web application',
    'status': 'planned'
}
project_id = security_testing_service.create_project(project_data, user_id=1)
```

## 📝 Примечания

- Все методологии будут загружаться из JSON файлов для удобства обновления
- Тесты могут быть автоматизированными или ручными
- Результаты тестов автоматически создают уязвимости в системе
- Метрики соответствия рассчитываются автоматически
