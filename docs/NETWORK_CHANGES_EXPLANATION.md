# 📡 Объяснение изменений сетевых настроек

## ❗ Важно: Я НЕ изменял системные сетевые интерфейсы

Я **не трогал** реальные сетевые интерфейсы на VM (eth0, enp0s3, wlan0 и т.д.). Все изменения касались только **Docker сетей** внутри docker-compose файлов.

---

## 🔍 Что было изменено:

### 1. Удалены `networks` и `depends_on` из docker-compose.yml

**Было (неправильно):**
```yaml
# services/backend/docker-compose.yml (раньше)
services:
  backend:
    depends_on:
      - database
    networks:
      - vuln_network

networks:
  vuln_network:
    driver: bridge
```

**Стало (правильно):**
```yaml
# services/backend/docker-compose.yml (сейчас)
services:
  backend:
    # Нет depends_on и networks, так как сервисы на разных VM
    # Связь через IP адреса (10.0.88.11:5432)
```

### 2. Почему это было изменено?

**Проблема:** `depends_on` и `networks` в docker-compose работают только для сервисов в **одном** docker-compose проекте на **одной** машине.

**Наша архитектура:**
- Frontend (10.0.88.10) - отдельная VM
- Backend (10.0.88.20) - отдельная VM  
- Database (10.0.88.11) - отдельная VM
- Parsers (10.0.88.23) - отдельная VM

Каждый сервис работает на своей VM, поэтому они общаются через **IP адреса**, а не через Docker сети.

---

## ✅ Что осталось:

### Docker сеть в `services/database/docker-compose.yml`

```yaml
networks:
  vuln_network:
    driver: bridge
    ipam:
      config:
        - subnet: 10.0.88.0/24
```

**Это НЕ влияет на системные интерфейсы!** Это внутренняя Docker сеть, которая используется только внутри контейнера PostgreSQL. Она **не изменяет** сетевые настройки хоста.

---

## 🔧 Как это работает сейчас:

### Связь между сервисами:

1. **Frontend (10.0.88.10) → Backend (10.0.88.20:5000)**
   - Nginx проксирует `/api/*` на `http://10.0.88.20:5000`
   - Связь через **IP адрес**, не через Docker сеть

2. **Backend (10.0.88.20) → Database (10.0.88.11:5432)**
   - Flask подключается к `psycopg.connect(host='10.0.88.11', port=5432)`
   - Связь через **IP адрес**, не через Docker сеть

3. **Parsers (10.0.88.23) → Database (10.0.88.11:5432)**
   - Парсеры подключаются к БД через IP адрес
   - Связь через **IP адрес**, не через Docker сеть

## ❓ Если возникли проблемы с сетью:

1. **Проверьте, что все VM в одной сети:**
   - Все должны быть в подсети `10.0.88.0/24`
   - Настроить в гипервизоре (VirtualBox, VMware)

2. **Проверьте firewall на VM:**
   ```bash
   sudo ufw status  # Ubuntu/Debian
   sudo firewall-cmd --list-all  # CentOS/RHEL
   ```

3. **Проверьте, что порты открыты:**
   ```bash
   sudo netstat -tulpn | grep :5432  # Database
   sudo netstat -tulpn | grep :5000  # Backend
   sudo netstat -tulpn | grep :80    # Frontend
   ```
