# 📥 Получение изменений с GitHub

Инструкция для второго разработчика: как получить изменения после того, как первый разработчик залил их на GitHub.

---

## 🎯 Быстрая инструкция

Когда первый разработчик залил изменения на GitHub, выполните:

```bash
# 1. Переключитесь на основную ветку
git checkout main-new

# 2. Получите изменения с GitHub
git pull origin main-new

# 3. Вернитесь на вашу рабочую ветку
git checkout feature/your-feature-name

# 4. Обновите вашу ветку из main-new
git rebase origin/main-new
```

---

## 📋 Подробная инструкция

### Шаг 1: Проверка текущего состояния

```bash
# Проверьте, на какой ветке вы находитесь
git branch

# Проверьте статус
git status

# Посмотрите последние коммиты
git log --oneline -5
```

### Шаг 2: Сохранение ваших изменений

**Если у вас есть незакоммиченные изменения:**

```bash
# Вариант 1: Закоммитьте их
git add .
git commit -m "WIP: сохранение текущей работы"

# Вариант 2: Временно сохраните (stash)
git stash
# Позже восстановите: git stash pop
```

**Если все уже закоммичено:**
- Пропустите этот шаг

### Шаг 3: Получение изменений с GitHub

```bash
# Переключитесь на основную ветку
git checkout main-new

# Получите информацию об изменениях (без применения)
git fetch origin

# Посмотрите, что изменилось
git log HEAD..origin/main-new --oneline

# Получите и примените изменения
git pull origin main-new
```

**Что происходит:**
- ✅ Git получает все новые коммиты с GitHub
- ✅ Автоматически сливает их с вашей локальной веткой main-new
- ✅ Обновляет файлы в вашей рабочей директории

### Шаг 4: Обновление вашей рабочей ветки

```bash
# Вернитесь на вашу рабочую ветку
git checkout feature/your-feature-name

# Обновите вашу ветку из main-new
git rebase origin/main-new
```

**Что происходит:**
- ✅ Ваши изменения "перемещаются" поверх новых изменений из main-new
- ✅ Вы получаете все новые функции и исправления
- ✅ Ваш код остается актуальным

### Шаг 5: Разрешение конфликтов (если есть)

Если Git сообщит о конфликтах:

```bash
# Git покажет файлы с конфликтами
git status

# Откройте файлы и разрешите конфликты
# (см. раздел "Решение конфликтов" ниже)

# После разрешения конфликтов
git add <файлы>
git rebase --continue
```

### Шаг 6: Отправка обновленной ветки

```bash
# Отправьте обновленную ветку на GitHub
git push origin feature/your-feature-name

# Если ветка уже была отправлена ранее, может потребоваться force push
# (только для ваших feature веток, не для main-new!)
git push --force-with-lease origin feature/your-feature-name
```

## 🔄 Ежедневный workflow

### Утром (когда начинаете работу)

```bash
# 1. Всегда начинайте с получения последних изменений
git checkout main-new
git pull origin main-new

# 2. Обновите вашу рабочую ветку
git checkout feature/your-feature-name
git rebase origin/main-new

# 3. Теперь можете продолжать работу
```

### В течение дня (периодически)

```bash
# Каждые 2-3 часа проверяйте, нет ли новых изменений
git fetch origin

# Посмотрите, что изменилось
git log HEAD..origin/main-new

# Если есть изменения, обновите вашу ветку
git rebase origin/main-new
```

### Вечером (перед завершением работы)

```bash
# Отправьте все ваши изменения
git push origin feature/your-feature-name

# Проверьте, нет ли новых изменений
git fetch origin
```

## 🔍 Проверка: получил ли я изменения?

### Способ 1: Проверка через git log

```bash
# Посмотрите последние коммиты
git log --oneline -10

# Должны быть видны коммиты первого разработчика
```

### Способ 2: Проверка через git status

```bash
git fetch origin
git status

# Если видите "Your branch is behind 'origin/main-new' by X commits"
# значит есть новые изменения, которые нужно получить
```

### Способ 3: Проверка конкретных файлов

```bash
# Посмотрите, когда файл был изменен
git log --oneline services/backend/app.py

# Должны быть видны коммиты первого разработчика
```

## ⚠️ Решение проблем

### Проблема: "Your branch is behind 'origin/main-new' by X commits"

**Решение:**
```bash
git checkout main-new
git pull origin main-new
git checkout feature/your-feature-name
git rebase origin/main-new
```

### Проблема: "Cannot rebase: You have unstaged changes"

**Решение:**
```bash
# Сохраните изменения
git stash

# Выполните rebase
git rebase origin/main-new

# Восстановите изменения
git stash pop
```

### Проблема: Конфликты при rebase

**Решение:**
1. Откройте файлы с конфликтами
2. Найдите маркеры `<<<<<<<`, `=======`, `>>>>>>>`
3. Разрешите конфликты (см. ниже)
4. Выполните:
```bash
git add <файлы>
git rebase --continue
```

### Проблема: "Updates were rejected" при push

**Решение:**
```bash
# Это нормально после rebase, используйте force-with-lease
git push --force-with-lease origin feature/your-feature-name
```

## 🔀 Решение конфликтов

### Что такое конфликт?

Конфликт возникает, когда:
- Первый разработчик изменил файл в main-new
- Вы изменили тот же файл в вашей ветке
- Git не может автоматически объединить изменения

### Как разрешить конфликт

#### Шаг 1: Найдите файлы с конфликтами

```bash
git status
# Покажет файлы с "both modified"
```

#### Шаг 2: Откройте файл с конфликтом

Вы увидите маркеры:

```python
<<<<<<< HEAD
# Ваш код
def your_function():
    return "your code"
=======
# Код первого разработчика
def their_function():
    return "their code"
>>>>>>> origin/main-new
```

#### Шаг 3: Разрешите конфликт

**Вариант 1: Оставить оба варианта**
```python
def your_function():
    return "your code"

def their_function():
    return "their code"
```

**Вариант 2: Объединить логику**
```python
def combined_function():
    your_code = "your code"
    their_code = "their code"
    return f"{your_code} + {their_code}"
```

**Вариант 3: Выбрать один вариант**
```python
# Оставить только код первого разработчика
def their_function():
    return "their code"
```

#### Шаг 4: Завершите разрешение

```bash
# Удалите маркеры конфликта из файла
# Добавьте файл
git add <файл>

# Продолжите rebase
git rebase --continue
```

## 📊 Визуализация процесса

```
До получения изменений:
┌─────────────────┐
│  GitHub         │
│  main-new       │ ← Первый разработчик залил изменения
│  [новые коммиты]│
└─────────────────┘
         │
         │ git pull
         ▼
┌─────────────────┐
│  Ваш компьютер  │
│  main-new       │ ← Старая версия
│  [старые коммиты]│
└─────────────────┘

После получения изменений:
┌─────────────────┐
│  Ваш компьютер  │
│  main-new       │ ← Обновлено!
│  [все коммиты]  │
└─────────────────┘
         │
         │ git rebase
         ▼
┌─────────────────┐
│  Ваша ветка     │
│  feature/your   │ ← Обновлена с новыми изменениями
│  [ваши + новые] │
└─────────────────┘
```

## ✅ Чеклист получения изменений

- [ ] Сохранены незакоммиченные изменения (stash или commit)
- [ ] Переключение на main-new
- [ ] Выполнен `git pull origin main-new`
- [ ] Проверены новые изменения (`git log`)
- [ ] Переключение на рабочую ветку
- [ ] Выполнен `git rebase origin/main-new`
- [ ] Разрешены конфликты (если есть)
- [ ] Отправлена обновленная ветка на GitHub

---

## 💡 Советы

1. **Получайте изменения часто** - минимум раз в день, лучше несколько раз
2. **Проверяйте перед началом работы** - всегда синхронизируйтесь утром
3. **Общайтесь с командой** - узнавайте, когда заливаются изменения
4. **Тестируйте после обновления** - убедитесь, что все работает
5. **Разрешайте конфликты сразу** - не откладывайте
