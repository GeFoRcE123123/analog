# 📁 ДОКУМЕНТАЦИЯ ПАПКИ `models/`

## 📋 Обзор

Папка `models/` содержит все модели данных, репозитории для работы с базой данных и адаптеры для преобразования данных. Здесь реализован паттерн Repository для абстракции доступа к данным.

## 🎯 Основной функционал

Папка `models/` обеспечивает:
- **Модели данных** (entities) для уязвимостей и операторов
- **Репозитории** для работы с PostgreSQL
- **Адаптеры** для преобразования между форматами
- **Управление подключениями** к базе данных
- **Инициализацию схемы** БД

## 📄 Файлы и их функционал

### 1. `entities.py`
**Назначение:** Определение моделей данных (сущностей)

**Основные классы:**

#### `Vulnerability`
**Назначение:** Модель уязвимости

**Поля:**
- `id` - уникальный идентификатор
- `title` - заголовок уязвимости
- `description` - описание
- `severity` - уровень серьезности (critical/high/medium/low)
- `status` - статус обработки (new/in_progress/completed и т.д.)
- `assigned_operator` - ID назначенного оператора
- `created_date` - дата создания
- `completed_date` - дата завершения
- `approved` - одобрена ли уязвимость
- `modifications` - количество модификаций
- `cvss_score` - CVSS оценка
- `risk_level` - уровень риска
- `category` - категория
- `cve_id` - CVE идентификатор
- `source_identifier` - идентификатор источника
- `published` - дата публикации
- `last_modified` - дата последнего изменения
- `vuln_status` - статус уязвимости
- `descriptions` - список описаний
- `metrics` - метрики (CVSS и т.д.)
- `weaknesses` - слабости (CWE)
- `configurations` - конфигурации (CPE)
- `references` - ссылки
- `vendor_comments` - комментарии вендоров
- `is_ai_related` - связана ли с AI
- `ai_confidence` - уверенность AI анализа
- `has_kev` - есть ли в KEV (Known Exploited Vulnerabilities)
- `has_cert_alerts` - есть ли CERT alerts

**Методы:**
- `mark_completed()` - отметить как завершенную
- `mark_approved()` - отметить как одобренную
- `request_modification()` - запросить модификацию
- `from_db_row()` - создать из строки БД

## 🔄 Паттерны проектирования

### Repository Pattern
Все репозитории следуют паттерну Repository для абстракции доступа к данным.

### Factory Pattern
`RepositoryFactory` использует паттерн Factory для создания репозиториев.

### Singleton Pattern
`DatabaseManager` использует паттерн Singleton для единственного экземпляра подключения.

## 📝 Примечания

- Поддерживается как legacy, так и modern схема БД
- Репозитории используют raw SQL для максимальной производительности
- Все репозитории должны быть thread-safe
- Рекомендуется использовать транзакции для операций изменения данных
