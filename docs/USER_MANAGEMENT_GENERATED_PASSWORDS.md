# Управление пользователями и сгенерированные пароли

## Обзор

В разделе **Управление пользователями** (доступен только администраторам) реализовано:

- Кнопка **«Добавить пользователя»** — открывает форму создания пользователя.
- В форме добавления и в форме редактирования есть кнопка **«Сгенерировать пароль»** — пароль генерируется и сохраняется в отдельную таблицу БД.
- Сохранённые пароли при открытии формы **редактирования** пользователя подставляются в поле пароля (только для админа, **не используются при входе** на сайт).

## Раздел «Управление пользователями»

- **URL:** `/admin/users`
- **Доступ:** только для пользователей с ролью `admin`.
- В меню: пункт «Управление пользователями» в выпадающем меню профиля (иконка пользователя в шапке).

## Кнопка «Добавить пользователя»

- Расположена справа от заголовка «Управление пользователями».
- По нажатию открывается модальное окно с формой:
  - Имя пользователя *
  - Email *
  - Пароль * (поле + кнопка **«Сгенерировать пароль»**)
  - Роль (user / admin)
  - Полное имя

## Кнопка «Сгенерировать пароль»

- Находится в модальном окне добавления пользователя и в модальном окне редактирования пользователя рядом с полем «Пароль».
- При нажатии:
  1. На сервере генерируется случайный пароль (буквы + цифры, длина по умолчанию 14).
  2. Пароль сохраняется в таблицу **`user_generated_passwords`** (при добавлении пользователя запись сначала создаётся с `user_id = NULL`, затем при создании пользователя привязывается к новому `user_id`).
  3. Сгенерированный пароль подставляется в поле «Пароль» в форме.

Сгенерированные пароли **не используются при входе на сайт** — вход по-прежнему выполняется по хешу пароля в таблице `users`. Таблица сгенерированных паролей нужна только для того, чтобы админ видел/подставлял пароль при добавлении и редактировании пользователя.

## Редактирование пользователя

- В таблице пользователей для каждого пользователя (кроме текущего админа) доступны кнопки **«Редактировать»** и **«Удалить»**.
- По нажатию «Редактировать» открывается модальное окно, данные пользователя загружаются через API, в поле «Пароль» подставляется сохранённый сгенерированный пароль (если он есть в БД).
- Админ может изменить пароль вручную или нажать «Сгенерировать пароль» — новый пароль попадёт в поле и при сохранении обновится и хеш в `users`, и запись в `user_generated_passwords`.

## База данных

### Таблица `user_generated_passwords`

Отдельная таблица для хранения сгенерированных паролей (в открытом виде, только для отображения админу при редактировании):

| Поле           | Тип           | Описание                                      |
|----------------|---------------|-----------------------------------------------|
| `id`           | SERIAL        | Первичный ключ                                |
| `user_id`      | INTEGER       | Ссылка на `users(id)`, может быть NULL до привязки |
| `plain_password` | VARCHAR(255) | Сохранённый пароль в открытом виде            |
| `created_at`   | TIMESTAMP     | Время создания записи                          |

- Уникальный индекс по `user_id` (один сохранённый пароль на пользователя; для записей с `user_id = NULL` может быть несколько «ожидающих» записей).
- При удалении пользователя соответствующие строки удаляются каскадно (`ON DELETE CASCADE`).

### Миграция для существующей БД

Если таблица ещё не создана, выполните:

```bash
psql -U <user> -d <database> -f services/database/migrate_user_generated_passwords.sql
```

Либо выполните SQL из файла `services/database/migrate_user_generated_passwords.sql` вручную.

## API (только для администраторов)

- **POST** `/api/admin/users/generate-password`  
  Генерация пароля и сохранение в `user_generated_passwords`.  
  Ответ: `{ "success": true, "password": "...", "record_id": <id> }`.  
  `record_id` передаётся при создании пользователя для привязки записи к новому `user_id`.

- **POST** `/api/admin/users`  
  Создание пользователя.  
  Тело: `username`, `email`, `password`, `role` (опционально), `full_name` (опционально), `generated_password_record_id` (опционально).  
  При указании `generated_password_record_id` запись в `user_generated_passwords` привязывается к созданному пользователю.

- **GET** `/api/admin/users/<user_id>`  
  Получение данных пользователя для редактирования, включая поле `generated_password` (из `user_generated_passwords`).

- **PUT** `/api/admin/users/<user_id>`  
  Обновление пользователя (имя, email, роль, полное имя, активность, пароль при необходимости).  
  Если передан `password`, обновляются хеш в `users` и запись в `user_generated_passwords`.

- **DELETE** `/api/admin/users/<user_id>`  
  Удаление пользователя (нельзя удалить себя).

## Безопасность

- Сгенерированные пароли хранятся в открытом виде только в таблице `user_generated_passwords`.
- Доступ к этой таблице и к отображению/подстановке паролей имеют только запросы, выполняемые от имени администратора (проверка `@admin_required`).
- При входе на сайт используется только хеш пароля из таблицы `users`; таблица `user_generated_passwords` при аутентификации не используется.
