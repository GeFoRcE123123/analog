#### 2.3 Database интеграция

**Добавить таблицы:**
```sql
-- Результаты ИИ-анализа
CREATE TABLE ai_analysis_results (
    id SERIAL PRIMARY KEY,
    vulnerability_id INTEGER REFERENCES turn(id),
    is_ai_related BOOLEAN,
    confidence FLOAT,
    keywords_found TEXT[],
    categories TEXT[],
    reasoning TEXT,
    analyzed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    model_version VARCHAR(50)
);

-- Ключевые слова для обучения
CREATE TABLE ai_keywords (
    id SERIAL PRIMARY KEY,
    keyword TEXT UNIQUE NOT NULL,
    category VARCHAR(50),
    weight FLOAT DEFAULT 1.0,
    source VARCHAR(50), -- 'manual', 'learned', 'extracted'
    usage_count INTEGER DEFAULT 0,
    accuracy FLOAT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Обучение модели
CREATE TABLE ai_training_data (
    id SERIAL PRIMARY KEY,
    vulnerability_id INTEGER REFERENCES turn(id),
    is_ai_related BOOLEAN NOT NULL,
    confirmed_by INTEGER REFERENCES users(id),
    confirmed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    context_text TEXT,
    extracted_keywords TEXT[],
    used_for_training BOOLEAN DEFAULT FALSE
);

-- Мониторинг сайтов
CREATE TABLE ai_monitoring_sites (
    id SERIAL PRIMARY KEY,
    url TEXT NOT NULL,
    site_name VARCHAR(255),
    parser_config JSONB,
    enabled BOOLEAN DEFAULT TRUE,
    last_check TIMESTAMP,
    check_interval INTEGER DEFAULT 3600, -- секунды
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Паспорта уязвимостей
CREATE TABLE ai_vulnerability_passports (
    id SERIAL PRIMARY KEY,
    vulnerability_id INTEGER REFERENCES turn(id),
    passport_data JSONB NOT NULL,
    generated_by_ai BOOLEAN DEFAULT TRUE,
    model_version VARCHAR(50),
    confidence FLOAT,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Метрики модели
CREATE TABLE ai_model_metrics (
    id SERIAL PRIMARY KEY,
    model_name VARCHAR(100),
    model_version VARCHAR(50),
    accuracy FLOAT,
    precision FLOAT,
    recall FLOAT,
    f1_score FLOAT,
    training_samples INTEGER,
    trained_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 🎯 ЧАСТЬ 3: Обучение ИИ-системы

### Задача
Обучить ИИ-систему на имеющихся данных об уязвимостях, чтобы она:
- Пополняла ключевые слова
- Училась отличать по контексту предложений
- Использовала отработанные уязвимости ИИ (те, в которых уверены)

### Требования

#### 3.1 Сбор обучающих данных

**Источники данных:**
- Таблица `turn` - все уязвимости в БД
- Таблица с подтвержденными ИИ-уязвимостями (если есть)
- Ручная разметка операторами/админами

**Процесс сбора:**
1. Извлечь все уязвимости из БД
2. Для каждой уязвимости извлечь:
   - `title` (название)
   - `description` (описание)
   - `affected_packages` (затронутые пакеты)
   - `references` (ссылки)
   - `cwe_ids` (CWE коды)
3. Создать интерфейс для ручной разметки (для админов)

#### 3.2 Извлечение ключевых слов

**Алгоритм:**
1. Анализ текста уязвимостей с подтвержденным `is_ai_related = TRUE`
2. Извлечение n-грамм (1-3 слова)
3. Подсчет частоты встречаемости
4. Фильтрация по релевантности
5. Добавление в таблицу `ai_keywords`

**Критерии добавления:**
- Минимальная частота встречаемости (например, 3+ раза)
- Высокая точность (только в ИИ-уязвимостях)
- Контекстная релевантность

#### 3.3 Обучение на контексте

**Метод:**
1. Использовать подтвержденные ИИ-уязвимости как положительные примеры
2. Использовать не-ИИ уязвимости как отрицательные примеры
3. Извлечение контекстных признаков:
   - Позиция ключевых слов в тексте
   - Окружающие слова (контекстное окно)
   - Структура предложений
   - Связи между словами
4. Обучение модели классификации (если используется ML)
5. Обновление весов ключевых слов на основе точности

#### 3.4 Механизм обучения

**Автоматическое обучение:**
- При добавлении новой подтвержденной ИИ-уязвимости
- При исправлении классификации оператором
- Периодическое переобучение (например, раз в неделю)

**Ручное обучение (админ):**
- Интерфейс для добавления ключевых слов
- Интерфейс для разметки уязвимостей
- Интерфейс для запуска обучения

**Сохранение результатов:**
- Обновление таблицы `ai_keywords`
- Сохранение метрик в `ai_model_metrics`
- Версионирование моделей

## 🎯 ЧАСТЬ 4: Мониторинг сайтов и адаптивный парсинг

### Задача
Запустить мониторинг HTML страниц из списков, адаптировать парсер под каждую страницу, отдавать в ИИ для категоризации.

### Требования

#### 4.1 Список сайтов для мониторинга

**Источники:**
- Существующие списки HTML страниц в проекте
- Конфигурационный файл со списком URL
- База данных `ai_monitoring_sites`

**Формат списка:**
```json
[
    {
        "url": "https://example.com/vulnerabilities",
        "site_name": "Example Security",
        "parser_type": "html",
        "selectors": {
            "vulnerability_list": ".vuln-list",
            "title": ".vuln-title",
            "description": ".vuln-description",
            "cve_id": ".cve-id"
        },
        "check_interval": 3600
    }
]
```

#### 4.2 Адаптивный парсер

**Функционал:**
1. Автоматическое определение структуры HTML страницы
2. Извлечение селекторов (CSS/XPath)
3. Адаптация под каждую страницу
4. Сохранение конфигурации парсера для каждого сайта
5. Обработка динамического контента (если нужно)

**Реализация:**
- `services/adaptive_html_parser.py` - адаптивный парсер
- Использование BeautifulSoup для парсинга
- Машинное обучение для определения структуры (опционально)
- Кэширование конфигураций парсеров

#### 4.3 Интеграция с ИИ

**Процесс:**
1. Парсер извлекает данные с HTML страницы
2. Данные нормализуются
3. Отправляются в ИИ-систему для классификации
4. Результат сохраняется в БД
5. Если `is_ai_related = TRUE`, уязвимость добавляется в основную БД

**Формат данных для ИИ:**
```json
{
    "title": "Название уязвимости",
    "description": "Описание...",
    "cve_id": "CVE-2024-12345",
    "affected_products": ["product1"],
    "references": ["url1"],
    "source": "example.com"
}
```

#### 4.4 Мониторинг

**Механизм:**
- Периодическая проверка сайтов (по расписанию)
- Обнаружение новых уязвимостей
- Автоматический парсинг и классификация
- Уведомления о новых ИИ-уязвимостях

**Управление:**
- Запуск/остановка мониторинга через API
- Настройка интервалов проверки
- Логирование результатов

- Адаптивный парсер для каждого сайта
- Автоматическая классификация через ИИ

## 🎯 ЧАСТЬ 5: Создание паспорта уязвимости при помощи ИИ

### Задача
Создать функционал генерации паспорта уязвимости с помощью ИИ на основе всех доступных данных.

### Требования

#### 5.1 Структура паспорта уязвимости

**Обязательные разделы:**
1. **Общая информация:**
   - CVE ID
   - Название
   - Краткое описание
   - Дата публикации
   - Дата последнего обновления

2. **Классификация:**
   - Является ли ИИ-уязвимостью
   - Уверенность классификации
   - Категории ИИ (если применимо)
   - CWE коды
   - OWASP категории

3. **Оценка рисков:**
   - CVSS score
   - EPSS score
   - Zero-day потенциал
   - Наличие эксплойта/PoC
   - CISA KEV статус

4. **Затронутые компоненты:**
   - Список затронутых продуктов
   - Версии
   - Платформы

5. **Рекомендации:**
   - Способы защиты
   - Патчи и обновления
   - Временные меры

6. **Дополнительная информация:**
   - Ссылки на источники
   - История изменений
   - Связанные уязвимости

#### 5.2 Генерация паспорта ИИ

**Процесс:**
1. Сбор всех данных об уязвимости:
   - Из БД (таблица `turn`, `cvelist`, и др.)
   - Из внешних источников (NVD, OSV, и др.)
   - Из результатов ИИ-анализа

2. Анализ данных ИИ:
   - Классификация (ИИ или нет)
   - Извлечение ключевых слов
   - Определение категорий
   - Оценка рисков

3. Генерация текста:
   - Использование LLM (если доступен) для генерации описаний
   - Или шаблонизация на основе данных

4. Формирование структурированного паспорта:
   - JSON формат для хранения
   - HTML формат для отображения
   - PDF формат для экспорта (опционально)

#### 5.3 API и интерфейс

**API endpoint:**
```python
POST /api/ai/generate-passport
{
    "vulnerability_id": 123,
    "format": "json" | "html" | "pdf",
    "include_ai_analysis": true
}
```

**Frontend:**
- Страница `/ai/passports` - список паспортов
- Страница `/ai/passports/<id>` - просмотр паспорта
- Кнопка "Создать паспорт" на странице уязвимости
- Экспорт в PDF/HTML

#### 5.4 Сохранение и версионирование

**Хранение:**
- Таблица `ai_vulnerability_passports`
- Версионирование при обновлении
- История изменений

**Обновление:**
- Автоматическое обновление при изменении данных
- Ручное обновление через интерфейс
- Перегенерация при обновлении ИИ-модели
