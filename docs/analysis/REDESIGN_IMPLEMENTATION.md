# 🏗️ РЕАЛИЗАЦИЯ РЕДИЗАЙНА

## 📋 СТРАТЕГИЯ РЕАЛИЗАЦИИ

После анализа выявлена проблема: **UI-маршруты (render_template) требуют данных из БД для рендеринга шаблонов**.

### Варианты решения:

#### Вариант 1: Frontend делает HTTP-запросы к Backend API (Рекомендуемый)
- Frontend VM: только статические HTML/CSS/JS, данные через AJAX
- Backend VM: API endpoints, данные из БД
- **Проблема**: Текущие шаблоны используют Jinja2 для рендеринга на сервере

#### Вариант 2: Frontend имеет доступ к БД только для чтения (Гибридный)
- Frontend VM: UI-маршруты с подключением к БД (только SELECT)
- Backend VM: API-маршруты с полным доступом к БД
- **Преимущество**: Минимальные изменения в коде
- **Недостаток**: Frontend все еще имеет доступ к БД

#### Вариант 3: Frontend проксирует запросы к Backend для рендеринга (Сложный)
- Frontend VM: Nginx + легкий Flask для проксирования
- Backend VM: Рендерит HTML через API endpoints
- **Сложность**: Требует значительных изменений

---

## ✅ ВЫБРАННЫЙ ПОДХОД: Вариант 2 (Гибридный) с постепенной миграцией

**Этап 1 (Текущий редизайн):**
- Frontend: UI-маршруты с подключением к БД (только для чтения данных)
- Backend: API-маршруты с полным доступом к БД
- Parsers: Фоновые задачи, без Flask

**Этап 2 (Будущее улучшение):**
- Постепенный переход к AJAX-загрузке данных
- Frontend становится полностью статическим

## ⚠️ ВАЖНЫЕ ЗАМЕЧАНИЯ

1. **Frontend требует БД для рендеринга**: Текущие шаблоны используют server-side рендеринг с данными из БД
2. **Постепенная миграция**: Сначала разделим маршруты, затем будем переходить к AJAX
3. **Обратная совместимость**: APP_ROLE='full' сохраняет старое поведение
