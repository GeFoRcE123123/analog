# 🚀 Автономный DevOps-агент

Автономный агент для автоматического запуска, настройки и отладки 4 VM системы Vulnerability Manager.

## 📋 Возможности

- ✅ **Автоматический запуск VM** (VirtualBox, QEMU/KVM, VMware, Vagrant)
- ✅ **Настройка автозапуска** через systemd на всех VM
- ✅ **Тестирование доступности** всех сервисов (Frontend, Backend, Database, Parsers)
- ✅ **Автоматическая диагностика** проблем (порты, контейнеры, подключения)
- ✅ **Автоматическое исправление** типичных ошибок
- ✅ **Детальный отчет** о состоянии системы

## 🚀 Использование

### Базовый запуск

```bash
./devops_agent.sh
```

### Что делает агент:

1. **Определяет платформу виртуализации** (VirtualBox, QEMU/KVM, VMware, Vagrant)
2. **Запускает все VM** (если они не запущены)
3. **Ожидает загрузки VM** (до 60 секунд на каждую)
4. **Настраивает автозапуск** через systemd на каждой VM
5. **Тестирует доступность** всех сервисов:
   - Frontend (10.0.88.10:80) - Nginx
   - Backend (10.0.88.20:5000) - Flask API
   - Database (10.0.88.11:5432) - PostgreSQL
   - Parsers (10.0.88.23) - Парсеры
6. **Диагностирует проблемы**:
   - Не запущенные контейнеры
   - Занятые порты
   - Ошибки подключения к БД
   - Проблемы с Nginx
7. **Автоматически исправляет**:
   - Запускает остановленные контейнеры
   - Останавливает конфликтующие сервисы (системный PostgreSQL)
   - Перезапускает сервисы при ошибках подключения
8. **Формирует отчет** в файл `devops_agent_report_YYYYMMDD_HHMMSS.txt`

## 🔧 Поддерживаемые платформы виртуализации

### VirtualBox

Агент автоматически определяет VirtualBox и пытается запустить VM по имени:
- `frontend-vm`, `Frontend`, `frontend`
- `backend-vm`, `Backend`, `backend`
- `database-vm`, `Database`, `database`
- `parsers-vm`, `Parsers`, `parsers`

### QEMU/KVM (libvirt)

Агент использует `virsh` для запуска VM:
- Ищет VM по имени в списке `virsh list --all`
- Запускает через `virsh start <vm_name>`

### VMware

Агент использует `vmrun` для запуска VM (требуется настройка путей к `.vmx` файлам).

### Vagrant

Агент использует `vagrant up` если найден `Vagrantfile` в текущей директории.

### Неизвестная платформа

Если платформа не определена, агент предполагает, что VM уже запущены и переходит к настройке и тестированию.

## 🔍 Диагностика проблем

### Автоматически исправляемые проблемы:

1. **Контейнер не запущен**
   - Агент запускает контейнер через `docker compose up -d`

2. **Системный PostgreSQL занимает порт 5432**
   - Агент останавливает системный PostgreSQL
   - Перезапускает Docker контейнер Database

3. **Backend не может подключиться к Database**
   - Агент проверяет доступность порта 5432
   - Перезапускает Backend после исправления Database

4. **Nginx показывает 502 Bad Gateway**
   - Агент проверяет доступность Backend
   - Проверяет конфигурацию Nginx

### Требующие ручного вмешательства:

1. **VM не загружается**
   - Проверьте настройки виртуализации
   - Проверьте доступность ресурсов (RAM, CPU, диск)

2. **SSH недоступен**
   - Проверьте сетевые настройки VM
   - Проверьте firewall правила

3. **Docker не установлен**
   - Установите Docker на VM:
    ```bash
    curl -fsSL https://get.docker.com -o get-docker.sh
    sudo sh get-docker.sh
    ```

4. **Проблемы с правами доступа**
   - Добавьте пользователя в группу docker:
    ```bash
    sudo usermod -aG docker $USER
    ```

## ⚙️ Конфигурация

Все настройки находятся в начале скрипта `devops_agent.sh`:

```bash
SSH_PASS='123'              # Пароль для SSH
SSH_USER='user'             # Пользователь для SSH
SSH_TIMEOUT=10              # Таймаут SSH подключения (секунды)
VM_BOOT_TIMEOUT=60          # Время ожидания загрузки VM (секунды)

# IP адреса VM
declare -A VMS=(
    ['frontend']='10.0.88.10'
    ['backend']='10.0.88.20'
    ['database']='10.0.88.11'
    ['parsers']='10.0.88.23'
)
```

## 🔐 Требования

- `bash` 4.0+
- `sshpass` (для автоматического SSH)
- `ping` (для проверки доступности VM)
- `curl` (для тестирования HTTP сервисов)
- Доступ к VM через SSH с паролем или ключом
- Права на запуск VM (VirtualBox, QEMU/KVM, VMware, Vagrant)

## 🐛 Отладка

Если агент не работает:

1. **Проверьте доступность VM:**
   ```bash
   ping 10.0.88.10
   ping 10.0.88.20
   ping 10.0.88.11
   ping 10.0.88.23
   ```

2. **Проверьте SSH подключение:**
   ```bash
   sshpass -p '123' ssh user@10.0.88.10 "echo 'OK'"
   ```

3. **Проверьте логи:**
   ```bash
   tail -f devops_agent_report_*.txt
   ```

4. **Запустите с отладкой:**
   ```bash
   bash -x devops_agent.sh
   ```
