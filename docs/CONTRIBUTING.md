## 🚀 Первоначальная настройка

### Шаг 1: Клонирование репозитория

```bash
# Клонируйте репозиторий
git clone https://github.com/GeFoRcE123123/analog.git
cd analog

# Проверьте текущую ветку
git branch -a

# Переключитесь на рабочую ветку (обычно main-new)
git checkout main-new
```

### Шаг 2: Настройка Git

```bash
# Настройте ваше имя и email (если еще не настроено)
git config --global user.name "Ваше Имя"
git config --global user.email "your.email@example.com"

# Настройте редактор по умолчанию (опционально)
git config --global core.editor "code --wait"  # VS Code
# или
git config --global core.editor "nano"  # Nano
```

### Шаг 3: Настройка окружения

```bash
# Создайте виртуальное окружение
python3 -m venv venv

# Активируйте виртуальное окружение
# На macOS/Linux:
source venv/bin/activate
# На Windows:
# venv\Scripts\activate

# Установите зависимости
pip install -r requirements.txt
```

### Шаг 4: Настройка SSH (для работы с VM)

См. подробные инструкции в [SSH_SETUP.md](./SSH_SETUP.md)

```bash
# Запустите скрипт настройки SSH
chmod +x scripts/setup_ssh.sh
./scripts/setup_ssh.sh --with-keys
```

## 🔄 Рабочий процесс (Workflow)

### Основной workflow для параллельной разработки

```
┌─────────────────────────────────────────────────────────┐
│  1. Получить последние изменения                        │
│     git pull origin main-new                            │
├─────────────────────────────────────────────────────────┤
│  2. Создать ветку для вашей задачи                     │
│     git checkout -b feature/your-feature-name           │
├─────────────────────────────────────────────────────────┤
│  3. Разрабатывать и коммитить изменения                │
│     git add .                                           │
│     git commit -m "Описание изменений"                  │
├─────────────────────────────────────────────────────────┤
│  4. Регулярно синхронизироваться с main-new            │
│     git fetch origin                                    │
│     git rebase origin/main-new                          │
├─────────────────────────────────────────────────────────┤
│  5. Отправить изменения                                 │
│     git push origin feature/your-feature-name           │
├─────────────────────────────────────────────────────────┤
│  6. Создать Pull Request (если используется)           │
│     или уведомить команду о готовности                  │
└─────────────────────────────────────────────────────────┘
```

### Ежедневный workflow

**Утром (начало работы):**

```bash
# 1. Получите последние изменения
git checkout main-new
git pull origin main-new

# 2. Обновите вашу рабочую ветку
git checkout feature/your-feature-name
git rebase origin/main-new
```

**Во время работы:**

```bash
# Делайте частые коммиты
git add .
git commit -m "Краткое описание изменений"

# Периодически отправляйте изменения
git push origin feature/your-feature-name
```

**Перед завершением работы:**

```bash
# Отправьте все изменения
git push origin feature/your-feature-name

# Убедитесь, что нет конфликтов
git fetch origin
git rebase origin/main-new
```

## 📝 Правила работы с Git

### Именование веток

Используйте понятные имена веток с префиксами:

- `feature/` - новая функциональность
  - `feature/user-authentication`
  - `feature/parser-redhat`
  
- `fix/` - исправление багов
  - `fix/database-connection`
  - `fix/ssh-timeout`
  
- `docs/` - документация
  - `docs/api-documentation`
  - `docs/setup-guide`
  
- `refactor/` - рефакторинг
  - `refactor/database-models`
  
- `test/` - тесты
  - `test/unit-tests`

### Сообщения коммитов

Используйте понятные сообщения на русском или английском:

**Хорошие примеры:**
```bash
git commit -m "Добавлена поддержка RedHat CVE парсера"
git commit -m "Исправлена ошибка подключения к БД при таймауте"
git commit -m "Обновлена документация по SSH настройке"
git commit -m "Рефакторинг модуля vulnerability_service"
```

**Плохие примеры:**
```bash
git commit -m "fix"  # Слишком короткое
git commit -m "изменения"  # Неинформативное
git commit -m "asdf"  # Бессмысленное
```

### Частота коммитов

- ✅ **Делайте коммиты часто** - каждые 1-2 часа работы
- ✅ **Коммитьте логически связанные изменения** вместе
- ✅ **Не коммитьте неработающий код** - код должен компилироваться
- ✅ **Коммитьте небольшими порциями** - легче откатывать и понимать

### Работа с удаленным репозиторием

```bash
# Получить изменения (без слияния)
git fetch origin

# Получить и слить изменения
git pull origin main-new

# Отправить изменения
git push origin your-branch-name

# Отправить и установить отслеживание ветки
git push -u origin your-branch-name
```

## 📐 Стандарты кода

### Python

- Используйте **PEP 8** стиль кодирования
- Максимальная длина строки: **120 символов**
- Используйте **type hints** где возможно
- Добавляйте **docstrings** для функций и классов

**Пример:**
```python
def parse_cve_data(cve_id: str, source: str) -> Dict[str, Any]:
    """
    Парсит данные CVE из указанного источника.
    
    Args:
        cve_id: Идентификатор CVE (например, 'CVE-2024-1234')
        source: Источник данных ('nvd', 'redhat', 'osv')
    
    Returns:
        Словарь с данными уязвимости
    
    Raises:
        ValueError: Если источник не поддерживается
    """
    # Ваш код здесь
    pass
```

### Именование

- **Функции и переменные**: `snake_case`
- **Классы**: `PascalCase`
- **Константы**: `UPPER_SNAKE_CASE`
- **Приватные методы**: начинаются с `_`

### Комментарии

- Комментируйте **сложную логику**
- Объясняйте **почему**, а не **что** (код должен быть самодокументируемым)
- Используйте комментарии на **русском** для бизнес-логики

## 🔀 Решение конфликтов

### Предотвращение конфликтов

1. **Работайте в отдельных ветках** - не коммитьте напрямую в `main-new`
2. **Часто синхронизируйтесь** - делайте `git pull` несколько раз в день
3. **Общайтесь с командой** - обсуждайте, кто над чем работает
4. **Работайте над разными файлами** - если возможно

### Если конфликт все же возник

#### Шаг 1: Получите последние изменения

```bash
git fetch origin
git rebase origin/main-new
```

#### Шаг 2: Git покажет конфликт

```
Auto-merging services/backend/app.py
CONFLICT (content): Merge conflict in services/backend/app.py
```

#### Шаг 3: Откройте файл с конфликтом

Вы увидите маркеры конфликта:

```python
<<<<<<< HEAD
# Ваш код
def your_function():
    pass
=======
# Код другого разработчика
def their_function():
    pass
>>>>>>> origin/main-new
```

#### Шаг 4: Разрешите конфликт

Решите, какой код оставить, или объедините оба варианта:

```python
# Объединенное решение
def your_function():
    pass

def their_function():
    pass
```

Удалите маркеры конфликта (`<<<<<<<`, `=======`, `>>>>>>>`)

#### Шаг 5: Завершите разрешение

```bash
# Добавьте разрешенные файлы
git add services/backend/app.py

# Продолжите rebase
git rebase --continue

# Если нужно отменить rebase
git rebase --abort
```

### Стратегии разрешения конфликтов

1. **Обсудите с командой** - если не уверены, что оставить
2. **Сохраните оба варианта** - если оба нужны
3. **Выберите более актуальный** - если один устарел
4. **Создайте новую функцию** - если логика разная

## 🧪 Тестирование

Перед коммитом убедитесь, что:

- ✅ Код компилируется без ошибок
- ✅ Нет синтаксических ошибок
- ✅ Импорты работают корректно
- ✅ Основная функциональность работает

```bash
# Проверка синтаксиса Python
python -m py_compile your_file.py

# Запуск тестов (если есть)
pytest tests/
```

## 📤 Отправка изменений

### Перед отправкой

```bash
# 1. Проверьте статус
git status

# 2. Убедитесь, что все изменения добавлены
git add .

# 3. Проверьте, что будет отправлено
git diff --cached

# 4. Сделайте коммит
git commit -m "Описание изменений"

# 5. Синхронизируйтесь с удаленным репозиторием
git fetch origin
git rebase origin/main-new

# 6. Отправьте изменения
git push origin your-branch-name
```

### Если push отклонен

```bash
# Получите последние изменения
git pull --rebase origin main-new

# Разрешите конфликты (см. выше)

# Отправьте снова
git push origin your-branch-name
```

## 💡 Советы и лучшие практики

### ✅ Делайте:

- ✅ **Частые коммиты** - каждые 1-2 часа
- ✅ **Понятные сообщения коммитов** - что и зачем изменили
- ✅ **Работайте в ветках** - не в main-new напрямую
- ✅ **Синхронизируйтесь регулярно** - несколько раз в день
- ✅ **Тестируйте перед коммитом** - код должен работать
- ✅ **Общайтесь с командой** - обсуждайте изменения

### ❌ Не делайте:

- ❌ **Не коммитьте пароли и секреты** - используйте .env
- ❌ **Не коммитьте большие файлы** - используйте Git LFS или исключите
- ❌ **Не коммитьте временные файлы** - проверьте .gitignore
- ❌ **Не коммитьте неработающий код** - сначала исправьте
- ❌ **Не перезаписывайте историю в общей ветке** - только в своих ветках
- ❌ **Не игнорируйте конфликты** - решайте их сразу
