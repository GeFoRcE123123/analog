## 🔄 Интеграция с существующей системой

### Совместимость с БДУ структурой

Система уже поддерживает БДУ ФСТЭК структуру (см. `docs/bdu/`). Grafana данные отлично интегрируются:

#### Заполняемые БДУ поля:
- ✅ `vendor` - "Grafana Labs"
- ✅ `product_name` - из Product
- ✅ `affected_versions` - из Fixed Versions
- ✅ `software_type` - определяется автоматически
- ✅ `remediation_method` - "Обновление ПО"
- ✅ `remediation_info` - форматированное описание
- ✅ `remediation_date` - дата публикации патча

#### Стратегия объединения источников:

```
┌─────────────┐
│   Grafana   │ ← Vendor-specific (remediation, versions)
└──────┬──────┘
       │
       ├──────→ Объединение по CVE ID
       │
┌──────┴──────┐
│     NVD     │ ← Стандартная классификация (CWE, CPE)
└──────┬──────┘
       │
       ├──────→ Дополнение российскими данными
       │
┌──────┴──────┐
│  БДУ ФСТЭК  │ ← Российские требования (BDU ID, русские описания)
└─────────────┘
```

## ⚠️ Важные замечания

### 1. HTML селекторы

**КРИТИЧЕСКИ ВАЖНО:** Селекторы в парсере являются **предположительными** и требуют уточнения после изучения реальной HTML структуры сайта Grafana.

**Что нужно сделать:**
1. Открыть https://grafana.com/security/security-advisories/
2. Изучить HTML структуру (DevTools → Elements)
3. Уточнить селекторы в `grafana_parser.py`

---

### 2. Rate Limiting

**Уважайте сервер Grafana:**
- Задержка между запросами: минимум 1 секунда
- Используйте кэширование
- Не делайте слишком частые полные синхронизации

---

### 3. Обработка ошибок

Парсер может столкнуться с:
- Изменением структуры HTML
- Сетевыми ошибками
- Отсутствием некоторых полей

**Рекомендации:**
- Всегда проверяйте логи
- Используйте `--dry-run` перед полным импортом
- Регулярно тестируйте парсер
