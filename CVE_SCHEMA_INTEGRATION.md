# Интеграция официальной CVE JSON схемы

## 📋 Источники

1. **CVE Schema Repository**: https://github.com/CVEProject/cve-schema.git
   - Официальная JSON схема для CVE записей
   - Версия 5.2.0 (последняя)
   - Поддерживается CVE Quality Working Group

2. **CVE Downloads**: https://www.cve.org/Downloads
   - Официальные JSON файлы CVE
   - Актуальные данные о всех уязвимостях
   - Регулярные обновления

## 🎯 Цели интеграции

1. Поддержка официального формата CVE JSON 5.x
2. Парсинг официальных JSON файлов с cve.org
3. Валидация данных по официальной схеме
4. Совместимость с существующей системой

## 📊 Структура CVE JSON 5.x

### Основные поля (по официальной схеме):

```json
{
  "dataType": "CVE_RECORD",
  "dataVersion": "5.0",
  "cveMetadata": {
    "cveId": "CVE-2024-XXXXX",
    "assignerOrgId": "...",
    "state": "PUBLISHED",
    "datePublished": "2024-01-01T00:00:00Z",
    "dateUpdated": "2024-01-01T00:00:00Z"
  },
  "containers": {
    "cna": {
      "providerMetadata": {...},
      "descriptions": [...],
      "affected": [...],
      "references": [...],
      "metrics": [...],
      "workarounds": [...],
      "solutions": [...]
    },
    "adp": {...}
  }
}
```

### Ключевые разделы:

1. **cveMetadata**: Метаданные CVE (ID, статус, даты)
2. **containers.cna**: Основные данные от CNA (CVE Numbering Authority)
3. **descriptions**: Описания уязвимости
4. **affected**: Затронутые продукты
5. **references**: Ссылки на дополнительную информацию
6. **metrics**: Метрики (CVSS, EPSS и др.)
7. **workarounds/solutions**: Решения и обходные пути

## 🔧 План интеграции

### Этап 1: Адаптер CVE JSON Schema (1-2 дня)
- Создать класс `CVEJSON5Adapter` для парсинга официального формата
- Маппинг полей CVE JSON 5.x на внутренние модели
- Валидация по схеме (опционально, используя JSON Schema)

### Этап 2: Загрузчик CVE JSON файлов (1-2 дня)
- Создать сервис для загрузки JSON файлов с cve.org
- Поддержка инкрементальных обновлений
- Кэширование и обработка больших файлов

### Этап 3: Интеграция с существующими парсерами (2-3 дня)
- Обновить NVD парсер для поддержки официального формата
- Интеграция с UnifiedParserService
- Совместимость с legacy форматом

### Этап 4: Валидация и нормализация (1-2 дня)
- Валидация по JSON Schema (опционально)
- Нормализация данных в единый формат
- Обработка ошибок и невалидных данных

## 📁 Структура файлов

```
services/
  cve_json5_adapter.py          # Адаптер для CVE JSON 5.x
  cve_json_loader.py            # Загрузчик JSON файлов с cve.org
  cve_schema_validator.py       # Валидатор по JSON Schema (опционально)
  
data/
  cve-schema/                   # Клонированный репозиторий схемы
    schema/
      v5.0/
      v5.1/
      v5.2/
```

## 🔗 Преимущества

1. **Официальный формат**: Использование стандартизированного формата
2. **Актуальность**: Прямая загрузка с официального источника
3. **Полнота данных**: Все поля из официальной схемы
4. **Совместимость**: Интеграция с существующей системой
5. **Расширяемость**: Легкое добавление новых полей
